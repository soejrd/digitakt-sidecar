# R05 — TRX-B2 and 44.1 kHz → 48 kHz conversion

Status: **DONE at the host benchmark level.** No Pi 4B or Digitakt hardware
performance claim is made. Source: mdkit `96157fe4fbda17bf4cae3168f52437d8232e6570`,
TRX-B2 (`mdkit_voice_trx_b2`, machine ID 28). The engine is run through its
public C API, not reimplemented.

## Contract and implementation

- TRX-B2 renders mono float32 at its documented native 44.1 kHz. Controls remain
  0–127; default controls are used unless a test says otherwise.
- [`r05_resampler`](../tools/r05_resampler.c) is a streaming, fixed-state,
  32-tap windowed-sinc converter at exactly 160/147. It owns a 64-float history,
  allocates nothing and never waits. Output frame *n* represents source position
  *n*·147/160. Normal processing retains the causal filter tail; `finish()` emits
  it using zero padding, so a complete stream has exactly `frames·160/147`
  output frames.
- [`r05_bench`](../tools/r05_bench.c) triggers the real engine, renders the
  reference at 44.1 kHz, then converts a complete stream. It compares continuous
  and ragged calls, checks converter amplitude/stopband behavior, retrigger
  envelope, pitch endpoints, a 60 s frame-count run, and host wall time.

## Measured host results

Generated by `./scripts/test_r05.sh`; compact results are in
[`evidence/r05/benchmark.json`](../evidence/r05/benchmark.json). This machine is
a desktop host, **not** a Pi 4B.

| Check | Measured |
| --- | --- |
| Native reference | 88,200 frames at 44,100 Hz; peak 0.999999881 |
| Complete conversion | 96,000 frames at 48,000 Hz = exact 160/147 |
| Block invariance | Continuous and ragged call sizes bit-identical in frame count and PCM |
| Engine block invariance | Native PCM identical for 257-frame and ragged application blocks |
| Impulse latency | Peak at output frame 87 for input frame 64; causal group delay ≈16 native samples (≈0.36 ms input time, before USB/device buffering) |
| Passband | 1 kHz peak amplitude 0.100003 for 0.1 input |
| Stopband | 22 kHz RMS 0.003437 vs 0.070711 passband reference: **−26.27 dB** |
| PTCH endpoints | Dominant reference tone 32 Hz (PTCH 0) vs 106 Hz (PTCH 127) after settling |
| Retrigger | Envelope restarts; second hit remains audible and decays |
| Duration/drift | 60 s native stream produces exactly 2,880,000 output frames |
| Host CPU | 2 s audio: engine 0.00135 s, converter 0.00119 s, combined 0.00250 s (≈800× realtime on this host) |

The CPU figures are wall-clock measurements on one desktop host with a warm
cache and no USB scheduling. They establish that conversion is cheap relative to
the engine in this environment; they do **not** establish Pi 4B headroom,
worst-case scheduling, thermal limits or a safe voice count.

## Limitations and release conditions

- 22 kHz rejection is −26.3 dB, not the 40 dB a steeper production filter would
  target. At 48 kHz output, images around 22 kHz can alias; this is acceptable
  for the R05 feasibility benchmark, but I04 should raise the tap count or use a
  steeper/oversampled design before claiming production audio quality.
- Pitch mapping is only an endpoint-direction measurement on the current engine;
  no note/velocity policy or calibrated semitone map is claimed. Those belong to
  I04.
- No Pi 4B benchmark, no hardware audio, no Digitakt flash and no live USB stream
  were used. H01 established physical transport separately; integrated latency
  and underrun/worst-case CPU remain H02/I04 work.
- 16-sample converter latency excludes USB packetization, buffering and device
  render latency. Do not add it to H01's round-trip figure as an integrated
  latency claim.

## Reproduce

```sh
./scripts/test_r05.sh
```

The script builds with C99 and `-Wall -Wextra -Werror`, writes the executable to
ignored `build/r05/`, and replaces the tracked compact JSON with a fresh run.
